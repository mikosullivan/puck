## Command-word convention

`7z` uses subcommand words for the mode: `a` (add / create), `x` (extract with paths), `e` (extract flat), `l` (list), `t` (test), `d` (delete from archive), `u` (update). The wrapper's builder should expose a `mode` property that maps to the right subcommand word.

## Common flags to expose

- **`a` / `x` / `e` / `l` / `t` / `d` / `u`** — subcommand word (via `mode`).
- **`-t<format>`** — archive format (`-t7z`, `-tzip`, `-tgzip`, `-ttar`, `-txz`, `-tbzip2`). Inferred from filename extension when not set, but required for some operations.
- **`-p<password>`** — password (encryption / decryption).
- **`-mx=<level>`** — compression level 0-9.
- **`-o<dir>`** — output directory for extraction (no space between `-o` and the path — 7z quirk).
- **`-y`** — assume yes to all prompts (non-interactive).
- **`-mhe=on`** — encrypt headers too (7z format only).

## Post-V1 caveats

7z is fairly permissive about argument order but sensitive about `-o<dir>` (no space) and about which flags are legal per mode. The wrapper's tests should cover each mode / flag combination it exposes.
