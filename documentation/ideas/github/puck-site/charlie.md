Charlie-specific rendering features that puck.uno (and Gitter post-V1) offers on top of the per-language format toggle. These are extras only Charlie gets — they exploit the Charlie→CJS transpiler that already lives in the engine.

## View as CJS

A toggle next to every Charlie code block (or `.charlie` file view) that swaps the displayed source from Charlie to its CJS representation. Click once to see what the engine actually consumes; click again to return to Charlie.

- **Off by default.** Author-faithful Charlie source is the baseline.
- **Per-viewer sticky.** Toggling on any Charlie block flips view-as-CJS on for every Charlie block on every page; stays on across sessions until flipped off.
- **CJS is always pretty-printed per your JSON style.** There's no "raw CJS" the author wrote — CJS is generated by the transpiler, so the displayed form uses the `json` section of your [`style.json`](https://puck.uno/documentation/ecoverse/formatting/formatting) (indent, line width, etc.).
- **Independent of the format toggle.** The Charlie format toggle reformats Charlie source per your Charlie style; view-as-CJS replaces the display entirely with CJS. They're separate switches that can be combined.

### Interaction with the format toggle

For any Charlie block, two independent switches give four states:

| Format-Charlie | View-as-CJS | What you see |
|---|---|---|
| off | off | Charlie source, as authored |
| on | off | Charlie source, reformatted per your Charlie style |
| off | on | CJS, pretty-printed per your JSON style |
| on | on | CJS, pretty-printed per your JSON style (Charlie style is irrelevant when displaying CJS) |

### Why this is cheap

The same Charlie→CJS transpiler that powers the Charlie format toggle, Differ's normalization, and the future Charlie web stack already produces the CJS — the view-as-CJS toggle just shows the intermediate output instead of running it back through the Charlie code generator. No new machinery required beyond the rendering switch and the toggle UI.

## Open questions

- The toggle's UI shape: a small icon next to the format toggle? A dropdown letting the viewer pick a display mode (Charlie / CJS / future "alternate representations" like AST or Lua-target)?
- Should the CJS view show line-by-line correspondence with the Charlie source (clickable mapping, hover-highlight)? Useful for learning; non-trivial to implement.
- Are there other "view alternate representation" toggles worth offering down the road — AST tree, transpiler intermediate stages, the Lua target Lucy generates? If so, view-as-CJS is the first of a small family and should be designed with room to grow.

## Out of scope

- Editing CJS directly. The CJS view is read-only; the user edits Charlie.
- View-as-CJS for languages other than Charlie. It's inherently Charlie-specific because CJS is Charlie's compilation target.
