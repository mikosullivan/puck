# Q0

## Purpose

Q0 is Mikobase's built-in query language. The name stands for "query zero" — it is the
baseline language all engines support. Future engines may also support additional query
languages such as GraphQL.

Every Q0 query is a JSON object sent to the engine via `engine.q0()`.

---

## Universal Namespace (UNS)

Class names in Q0 use UNS strings — a URL without the `https://` protocol prefix.

Examples:

- `mikobase.com/record`
- `mikobase.com/reference`
- `foo.com/character`

---

## Actions

The current Q0 actions are:

- `select` — read records
- `create` — create a new record
- `update` — update an existing record
- `delete` — delete a record
- `transaction` — start a transaction
- `commit` — commit a transaction
- `rollback` — roll back a transaction

---

## `select`

A `select` query reads current visible records.

```json
{"action": "select"}
```

An unfiltered `select` returns all active records.

### Filtering by `pk`

`pk` selects a single record by its primary key.

```json
{"action": "select", "pk": "92677339-df86-4f68-9397-999e40cf2c40"}
```

### Filtering by `class` / `classes`

`class` and `classes` are aliases. Both may be a string or an array of strings. When both
are present, their values are combined: each is normalized to an array, then the arrays are
union-merged (duplicates removed). Using both together produces a warning in the response.

Class filtering is always inheritance-aware — subclasses are always included.

```json
{"action": "select", "class": "foo.com/character"}
```

```json
{"action": "select", "classes": ["foo.com/hero", "foo.com/villain"]}
```

```json
{"action": "select", "class": "foo.com/hero", "classes": ["foo.com/villain", "foo.com/npc"]}
```

### `count`

Every `select` resultset includes a `count` of the number of records actually returned,
after `limit` and `offset` are applied.

```python
results = engine.q0({"action": "select", "class": "foo.com/character", "limit": 10})
print(results.count)  # number of records returned, up to 10
for record in results:
    print(record)
```

### `limit` and `offset`

`limit` restricts the number of records returned. `offset` skips the first N records.
Both are optional integers.

```json
{
    "action": "select",
    "class": "foo.com/character",
    "limit": 10,
    "offset": 20
}
```

### `sort` / `sorts`

`sort` is a single sort path. `sorts` is an array of sort paths. When both are present,
`sort` is applied first, then each entry in `sorts` is appended in order. `sort` always
takes priority over `sorts` in the combined sequence. Using both together produces a
warning in the response.

A sort path is an array of bucket keys, like `path`, with an optional trailing qualifier
object.

```json
{"action": "select", "class": "foo.com/character", "sort": ["name", "family"]}
```

```json
{"action": "select", "class": "foo.com/character", "sort": ["name", "family", {"case-sensitive": false}]}
```

```json
{
    "action": "select",
    "class": "foo.com/character",
    "sorts": [
        ["name", "family", {"case-sensitive": false, "collapse": true}],
        ["age", {"reverse": true}]
    ]
}
```

Qualifiers:

| Qualifier | Description |
|---|---|
| `reverse` | If `true`, sort descending. Defaults to `false` (ascending). |
| `case-sensitive` | If `false`, sort strings case-insensitively. Defaults to `true`. |
| `collapse` | If `true`, normalize whitespace before sorting. Defaults to `false`. |

Null values always sort last, regardless of `reverse`.

If `sort` and `sorts` are both omitted, result ordering is undefined.

## Narrowing

Q0 is built around narrowing. A query starts from a root set of records and progressively
narrows it through a sequence of steps.

### `then`

`then` narrows the current result set to a subset. It is an AND operation — only records
matching the `then` condition survive.

```json
{
    "action": "select",
    "class": "foo.com/character",
    "then": {
        "path": ["rank", "Captain"]
    }
}
```

`then` can be nested:

```json
{
    "action": "select",
    "class": "foo.com/character",
    "then": {
        "path": ["rank", "Captain"],
        "then": {
            "path": ["species", "Human"]
        }
    }
}
```

Adding `"not": true` to a `then` block negates the condition — only records that do NOT
match survive:

```json
{
    "action": "select",
    "class": "foo.com/character",
    "then": {
        "not": true,
        "path": ["name", "family", "Kirk"]
    }
}
```

### `all`

`all` is an array of sub-queries. The record must match every sub-query (AND logic).

```json
{
    "action": "select",
    "class": "foo.com/character",
    "all": [
        {"path": ["Starfleet Academy", {"truthy": true}]},
        {"path": ["officer", {"truthy": true}]}
    ]
}
```

### `any`

`any` is an array of sub-queries. The record must match at least one sub-query (OR logic).

```json
{
    "action": "select",
    "class": "foo.com/character",
    "any": [
        {"path": ["name", "family", "Picard"]},
        {"path": ["name", "family", "Spock"]},
        {"path": ["name", "family", "Archer"]},
        {"path": ["name", "family", "McCoy"]}
    ]
}
```

`all`, `any`, and `then` can be combined and nested:

```json
{
    "action": "select",
    "class": "foo.com/character",

    "any": [
        {"path": ["name", "family", "Picard"]},
        {"path": ["name", "family", "Spock"]},
        {"path": ["name", "family", "Archer"]},
        {"path": ["name", "family", "McCoy"]}
    ],

    "all": [
        {"path": ["Starfleet Academy", {"truthy": true}]},
        {"path": ["officer", {"truthy": true}]}
    ],

    "then": {
        "not": true,
        "path": ["commands", {"includes": "Reliant"}]
    }
}
```

## `path`

`path` traverses nested keys in `bucket` and matches the final value. Each element except
the last is a hash key to navigate into. The last element is either a literal value or an
operator object.

Simple equality:

```json
{"path": ["rank", "Captain"]}
```

Nested traversal:

```json
{"path": ["name", "family", "Janeway"]}
```

### Path Operators

The last element of a `path` array may be an operator object instead of a literal value.

**String operators:**

| Operator | Description |
|---|---|
| `{"value": "...", "case-sensitive": false}` | Case-insensitive equality |
| `{"contains": "..."}` | Substring match |
| `{"starts-with": "..."}` | Prefix match |
| `{"ends-with": "..."}` | Suffix match |

**Number operators:**

| Operator | Description |
|---|---|
| `{"gt": n}` | Greater than |
| `{"lt": n}` | Less than |
| `{"gte": n}` | Greater than or equal |
| `{"lte": n}` | Less than or equal |

**Array operators:**

| Operator | Description |
|---|---|
| `{"includes": "..."}` | Array contains this element |
| `{"includes_all": [...]}` | Array contains all of these elements |
| `{"includes_any": [...]}` | Array contains at least one of these elements |

**Existence and truthiness operators:**

| Operator | Description |
|---|---|
| `{"exists": true}` | Field is present and non-null |
| `{"exists": false}` | Field is absent or null |
| `{"truthy": true}` | Field is present, non-null, and truthy |
| `{"any": true}` | Matches any value (note: distinct from the `any` narrowing operator) |

## Placeholders

Placeholders allow query templates to be reused with minimal changes. They are defined at
the top level of a query (or inside a `then` block) and referenced anywhere in the query
using `{"placeholder": "name"}`.

```json
{
    "action": "select",
    "placeholders": {
        "name": "Picard"
    },
    "path": ["name", "family", {"placeholder": "name"}]
}
```

Placeholders can themselves reference other placeholders:

```json
{
    "action": "select",
    "placeholders": {
        "name": "Picard",
        "family_match": {
            "value": {"placeholder": "name"},
            "case-sensitive": false,
            "collapse": true
        }
    },
    "path": ["name", "family", {"placeholder": "family_match"}]
}
```

### Scoping and Inheritance

Placeholders defined in an outer query are inherited by all nested `then` blocks. An inner
`then` block may define its own `placeholders` that shadow inherited ones with the same
name. There is no mechanism to explicitly remove an inherited placeholder — only shadowing
is possible.

```json
{
    "action": "select",
    "placeholders": {"rank": "Captain"},
    "path": ["rank", {"placeholder": "rank"}],
    "then": {
        "placeholders": {"rank": "Commander"},
        "path": ["rank", {"placeholder": "rank"}]
    }
}
```

### Placeholder Validation

Placeholder validation runs without executing the query. Only checks that can be performed
statically are included — errors that would only surface at runtime (e.g. a placeholder
never reached due to short-circuit evaluation) are not reported.

```python
engine.validate(query)               # shorthand for run_all
engine.validator.run_all(query)      # runs all validation methods
engine.validator.placeholders(query) # placeholder checks only
```

### Rules

- Placeholders are resolved dynamically at the moment they are encountered during
  execution. There is no upfront resolution pass — placeholder values are looked up
  each time the placeholder is reached, not once at the start of the query.
- Circular references are an error only if the circular reference is actually reached.
- Referencing an undefined placeholder is an error only if it is actually reached.
- A placeholder never reached causes no error.
- Placeholders are local to the query and not reusable across separate queries.
- A placeholder may resolve to any JSON value.

## `create`

Creates a new record.

```json
{
    "action": "create",
    "class": "foo.com/character",
    "bucket": {"name": "Spock"}
}
```

Rules:

- `bucket` is required and must be a JSON object.
- `class` is optional. If omitted or `null`, the engine uses the default class
  `mikobase.com/record`.
- The engine generates the `record_pk`.
- Successful response includes `success: true` and the new `pk` in `results`.

---

## `update`

Updates an existing record.

```json
{
    "action": "update",
    "pk": "92677339-df86-4f68-9397-999e40cf2c40",
    "bucket": {"name": "Spock"}
}
```

Rules:

- `pk` is required.
- `bucket` is required unless only changing the class.
- `class` is optional. If omitted, the class is unchanged.
- Updating a deleted record is an error.

---

## `delete`

Deletes a record by writing a tombstone version with `active = false`.

```json
{
    "action": "delete",
    "pk": "92677339-df86-4f68-9397-999e40cf2c40"
}
```

Rules:

- `pk` is required.
- `if_exists: true` makes the delete idempotent — deleting an already-deleted or
  non-existent record returns success with `deleted: false`.
- The tombstone clears all business fields (`bucket`, `class_pk`, `custom_classes`).
- Deleted records are excluded from normal `select` queries.
- Historical reads at a cutoff timestamp may still return records that were active at
  that time.

---

## Responses

### Success

```json
{"success": true, "results": {"pk": "92677339-df86-4f68-9397-999e40cf2c40"}}
```

### Warnings

A response may include a `warnings` array alongside a successful result. Warnings indicate
non-fatal issues — the query executed normally, but something about the request was
redundant or suspicious.

```json
{"success": true, "results": {...}, "warnings": [{"id": "redundant_fields", "details": {"fields": ["class", "classes"]}}]}
```

### Failure

```json
{
    "success": false,
    "errors": [
        {"id": "invalid_request", "details": {"missing_fields": ["bucket"]}}
    ]
}
```

---

## Transactions

Transactions are started with `action: "transaction"` and managed via `commit` and
`rollback`. See the requirements document for the full transaction model.

---

## Pass-through Fields

`misc` and `enterprise` are allowed at the top level of any Q0 request and are always
ignored by core storage engines. Custom engines in a chain may use them for extension
metadata.

---

## Error IDs

| Error ID | Meaning |
|---|---|
| `invalid_request` | Malformed request (missing fields, wrong types, unknown fields) |
| `class-not-found` | Class path does not resolve to a known class |
| `record_not_found` | Target `pk` does not exist |
| `record_deleted` | Target record exists but is already deleted |
| `invalid-mode` | Syntactically invalid connection mode string |
| `mode-not-supported` | Valid mode string not supported by this engine |
| `read-only-connection` | Write action attempted on a read-only connection |
| `action-not-supported` | Action not implemented by this engine |
| `request-too-large` | Request exceeds engine-configured size limit |
| `transaction-not-found` | Unknown transaction id |
| `transaction-invalidated` | Transaction id invalidated by an ancestor rollback |
