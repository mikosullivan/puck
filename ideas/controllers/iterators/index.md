## The usual features

Caspian has the loop features you'd expect. A tour:

**while:**

~~~caspian
$x = 0

while ($x < 10)
	puts $x
	$x = $x + 1
end
~~~

**Collection iteration with `.each`:**

~~~caspian
[1, 2, 3].each do($n)
	puts $n
end
~~~

**Numeric helper:**

~~~caspian
5.times do($i)
	puts $i
end
~~~

**Break out early:**

~~~caspian
$people.each do($person)
	if $person.match?
		break
	end

	process $person
end
~~~

**Break past the innermost loop:**

~~~caspian
$states.each do($state)
	$state.cities.each do($city)
		$city.streets.each do($street)
			if $street.name == 'target'
				break 2       # exits the outermost of the three
			end

			catalog $street
		end
	end
end
~~~

**Skip an iteration:**

~~~caspian
$people.each do($person)
	if $person.inactive?
		next
	end

	process $person
end
~~~

Bare `break` / `next` are sugar for calling `.break` / `.next` on the iterator of the innermost enclosing loop — see § Iterators as objects. `break N` targets the loop N levels up (so `break` and `break 0` are equivalent; breaking an outer loop cascades to end any inner loops still running); `next N` follows the same numbering. If N exceeds the enclosing-loop count, either raises.

## Break with a value

`break` can carry a value; that value becomes the loop's return value. The whole loop expression is assignable:

~~~caspian
$found = while ($record = $db.next)
	if $record.match?
		break $record
	end
end
~~~

If the loop never breaks (runs to completion normally), the returned value is `null`.

## Iterators as objects

Iterators are first-class objects in Caspian. Iterators are generated by primitive loop methods like `while` and `n.times`. A developer never builds an iterator object from scratch (but we're working on that — see [v-1-x](https://www.puck.uno/ideas/v-1-x/)).

To get an iterator, use one of the primitive loop structures with an `as $name` binding. Each loop produces its own iterator:

~~~caspian
$x = 0

while ($x < 3) as $outer
	$y = 0
	
	while ($y < 3) as $inner
		# $outer is the iterator for the outer while
		# $inner is the iterator for the inner while
		# each is a distinct object created by its own primitive loop
		$y = $y + 1
	end

	$x = $x + 1
end
~~~

Because each iterator is a distinct object, breaking or advancing a specific loop is a matter of calling a method on THAT iterator. The inner iterator's `.break` exits the inner loop; the outer iterator's `.break` exits the outer.

~~~caspian
# Break out of the inner loop from within the inner loop
$rooms.each do($room) as $room_iter
	$room.people.each do($person) as $person_iter
		if $person.blocked?
			$person_iter.break     # exits the inner .each; scanning continues to the next room
		end

		process $person
	end
end

# Break out of the OUTER loop from within the inner loop
$rooms.each do($room) as $room_iter
	$room.people.each do($person) as $person_iter
		if $person.emergency?
			$room_iter.break       # exits the outer .each entirely
		end

		handle $person
	end
end
~~~

An iterator is a specific kind of **controller**. Iterators are the controllers that come out of primitive loops, carrying loop-control methods like `.break` and `.next`.

### How bare `break` and `next` resolve

Bare `break` in a block dispatches to `.break()` on the current call's controller — `%call['controller']`.

~~~caspian
method &each()
	while ($record = @cache.next) as $loop
		iterate $loop, $record
	end
end

$results.each do($record)
	break         # calls %call['controller'].break()
end
~~~

Trace: `iterate` set `$caller.controller = $loop` before calling the block, so the block's `%call['controller']` holds the iterator from each's while. `break` dispatches to that iterator's `.break()`, signaling the while to exit.

The block doesn't need `as $loop` for `break` to work. Naming with `as` gives the iterator a variable in the block's scope; the controller slot is populated by `iterate` regardless. `next` follows the same rule.

Same mechanism works inside a primitive loop's own body — the loop invokes its body as a callable with its own iterator wired into the body's `%call['controller']`. One uniform rule: bare `break` = `.break()` on the current call's controller.

**The controller must be explicitly passed down.** Each frame has its own `%call['controller']`; the engine doesn't walk up the call stack looking for one. If the block calls a helper function without wiring an iterator into the helper's caller, the helper's controller slot is null, and a bare `break` inside the helper raises. To let a helper control the enclosing loop, the block passes the iterator to it explicitly — see § Passing iterators to other functions. Fail-loud-early: no silent-no-op when there's no controller in scope.

### Yielding an iterator

#### Short form

~~~
iterate $loop, [arg1...]
~~~

`iterate` invokes `%call.blocks[0]` — the first block passed to the method — with `$loop` wired as the block's controller and the remaining args passed through to the block's `.call`.

~~~caspian
method &records
	$db = somedb

	while ($record = $db.next) as $loop
		iterate $loop, $record
	end
end
~~~

`iterate` doesn't create a new iterator each time it fires — the first arg IS whatever iterator the calling scope holds (typically `$loop` from the enclosing primitive loop), unchanged across every invocation.

`yield ARGS...` is the sibling primitive when the block doesn't need an iterator wired — same "call block[0]" behavior, no controller involvement. If the method has no block, either bwc raises.

#### Long form

Under the hood, `iterate` expands to the full caller-build-and-call sequence:

~~~caspian
method &records
	$db = somedb

	while ($record = $db.next) as $loop
		$caller = %call.blocks[0].caller.new
		$caller.controller = $loop
		$caller.call $record
	end
end
~~~

Walk-through:

1. Build a caller for the block.
2. Put the iterator in the caller's `.controller` slot; the block's `as $name` binding will pick it up when the block runs.
3. Invoke, passing args through.

Reach for the long form when `iterate` doesn't expose what you need — DSL wiring on the caller (see [caller/dsl](https://www.puck.uno/requirements/functions/caller/dsl)), multiple invocations with different arg shapes, custom parameter setup, or reusing one caller across many iterations without rebuilding it.

### Passing iterators to other functions

Iterators are objects just like everything else in Caspian. They can be stored in variables, passed as arguments, held in collections — anything you can do with any other object. Where an iterator "lives" is determined by where a reference to it is held, not by which stack frame originally created it.

An iterator passed several layers down the call chain can still `break` or `next` its underlying loop:

~~~caspian
function &validate_record($record, $iter)
	if $record.corrupted
		raise CorruptedRecord.new($record)
	end

	if $record.type == 'sentinel'
		$iter.break                # exits the while loop up in the caller
	end

	if $record.type == 'skip'
		$iter.next                 # skips to the next iteration up in the caller
	end

	&process_record $record
end

while ($record = $db.next) as $loop
	&validate_record $record, $loop
end
~~~

The `while` creates `$loop`. The block passes it down to `&validate_record` as `$iter`. When `&validate_record` calls `$iter.break`, it's calling `.break` on the SAME iterator object the while created — the two variable names, `$loop` and `$iter`, hold references to one object. The break signal propagates back up through the function-call chain and exits the while.

Same for `.next`, and for any other method the iterator exposes. Deep passing works because iterators are just objects — calling a method on one always reaches the underlying loop, no matter how many function-call layers separate the two.
